# character (dog) frames

One folder per character id (`puggie`, `chowie`, `frenchie`, `tuckie`,
`huskie`, `corgie`, `shibie`, `goldie`), each with the same 9 frames as the pug
(`<id>-idle.svg`, `-blink`, `-left-paw-down`, `-right-paw-down`, `-both-down`,
`-left-paw-half`, `-right-paw-half`, `-winner`, `-winner-small`) plus
`<id>-head.svg` (the idle frame cropped to the head, for 32px lists).
The mapping lives in `src/ts/components/pages/test/character-frames.ts`.

Same rules as `../pug/README.md` (512 canvas, colours via theme vars only, no
scripts). Dog-specific tokens (`--chow-fill`, `--corgie-ear`, …) fall back to
the art's colours; `src/styles/character-mono.scss` maps them for mono themes.

Do not edit by hand: `pnpm sync-characters` (in `frontend/`) copies the art
kit's final frames (`ART_DIR`, default
`art/sketches/frames` at the repo root, generated by `python3 art/render8.py`) and

- gives every dog puggie's cream sticker halo (`--pug-fill`) so the visible rim
  is the same cream border + dark `--pug-ink` line,
- rounds path data to whole units and drops redundant attributes (invisible at
  ≤200px; keeps every frame ≤40KB),
- aliases repeated `var(--token, #fallback)` colours to short root custom
  properties (the fallback stays on the root).

`pnpm check-characters` asserts viewBox, no scripts/handlers, theme-var-only
colours, ≤40KB per frame, ≤60KB gzip per dog and identical desk geometry, and
prints the size table.
